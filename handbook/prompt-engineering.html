Анатомия промпта: формат, роль, контекст и ограничения

Input Format

Организация входа: сообщения, инструкции, документы и примеры должны быть различимы. Выбор Markdown, XML-подобной разметки или JSON сам по себе не гарантирует качество.

Полный разбор

System Prompting

Устойчивые правила приложения передаются предусмотренным API способом. Они не являются дообучением и не заменяют проверки результата.

Полный разбор

Role & Behavior

Роль задаёт функцию, поведение — наблюдаемые требования к ответу. Назначение экспертом не добавляет фактов, доступа и полномочий.

Полный разбор

Contextual Prompting

Факты текущей задачи: аудитория, продукт, режим аккаунта и нужные документы. Отсутствующие сведения нельзя восстановить одной формулировкой.

Полный разбор

Constraining Prompts

Границы задачи, источников, действий и формата. Нужен корректный путь при неизвестном и отдельная программная проверка обязательных условий.

Полный разбор

Структурированный ответ и вызов функций

Structured Outputs

Формат результата для программы. Просьба ответить JSON и ограниченная генерация по схеме — разные уровни контроля; правильная форма не доказывает истинность значений.

Полный разбор

Function Calling

Модель предлагает именованную операцию и аргументы; исполняющая среда проверяет и выполняет её. Сформированный вызов ещё не выполненное действие.

Полный разбор

Техники промптинга: примеры, объяснения и действия

Zero-Shot

Инструкция и текущие данные без демонстрационных пар. Это не означает отсутствие контекста или обучения модели.

Полный разбор

Few-Shot

Несколько примеров входа и выхода показывают нужный шаблон. Это работа через контекст, а не обновление параметров.

Полный разбор

ReAct

Выбор действия, реальное исполнение инструмента и наблюдение результата образуют цикл. Текст о якобы выполненном поиске не является наблюдением.

Полный разбор

Chain-of-Thought Prompting

Исследовательская техника с промежуточными шагами решения. Проверяемое объяснение, внутренние вычисления и гарантия правильности — разные понятия.

Полный разбор

Prompt caching и потоковая выдача ответа

Prompt Caching

В описанном LLM API повторно используется обработка совпадающего префикса, а ответ генерируется заново. Это отличается от кэша готовых ответов приложения.

Полный разбор

Streaming Responses

Ответ приходит событиями и фрагментами до завершения. Ранний показ не гарантирует ускорение полного ответа; структурированные данные нужно собирать и проверять.

Полный разбор

Что легко перепутать

  • Роль эксперта не предоставляет знаний или доступа.
  • Ограничения в промпте не заменяют программных проверок.
  • Валидный JSON может содержать неверный факт.
  • Предложенный вызов функции — ещё не исполненная операция.
  • Few-shot не меняет параметры модели.
  • Развёрнутое объяснение не служит доказательством правильности.
  • Prompt caching префикса не равен кэшу готового ответа.
  • Первый фрагмент потока не равен завершённому результату.
